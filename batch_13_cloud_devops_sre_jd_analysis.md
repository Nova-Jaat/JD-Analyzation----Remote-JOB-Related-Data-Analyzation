**Q2: During a migration wave cutover, an application server on RHEL 9 in AWS cannot establish a low-latency connection to the on-premise Oracle Exadata database over the hybrid link. How do you isolate the problem?**

> 1. **Layer 3 (Routing & IP):** Verify AWS Route Tables have the on-premise Exadata CIDR routed to the Transit Gateway / Direct Connect Gateway. Check the local RHEL 9 routing table with `ip route show` to confirm the default gateway.
> 2. **Layer 4 (Transport & Firewall):** Verify AWS Security Groups and Network ACLs allow egress on Oracle SQL*Net port (default `1521`). On the RHEL 9 host, test reachability and latency using `nc -zv <exadata-ip> 1521` and `traceroute -T -p 1521 <exadata-ip>`.
> 3. **MTU & Packet Fragmentation:** Hybrid Direct Connect and VPN tunnels often suffer from MTU mismatches. Jumbo frames (9001 MTU) in AWS will drop if on-prem or VPN enforces 1500 or 1420 MTU. I run `ping -M do -s 1472 <exadata-ip>` to test Path MTU Discovery (PMTUD).
> 4. **DNS Resolution:** Ensure `/etc/resolv.conf` points to the Amazon Route 53 Resolver inbound endpoint that forwards queries for the on-premise database domain to internal DNS servers."
