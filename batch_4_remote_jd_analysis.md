### Essential Azure Interview Talking Points:
1. **AKS Networking (Kubenet vs Azure CNI):**
   * *Talking Point:* *"Kubenet uses internal NAT routing with smaller VNet subnet footprints, whereas Azure CNI assigns routable VNet IP addresses directly to each Pod for lower latency and direct enterprise connectivity."*
2. **Azure RBAC vs Entra ID:**
   * *Talking Point:* *"Entra ID manages identities (Users, Groups, Service Principals, Managed Identities), while Azure RBAC assigns permissions to those identities scoped to a Management Group, Subscription, Resource Group, or individual Resource."*
3. **Terraform Azure Provider (`azurerm`):**
   * *Talking Point:* *"Azure resources require explicit Resource Group association (`resource_group_name = azurerm_resource_group.rg.name`) and explicit region binding (`location = var.region`). Remote state is stored in an Azure Blob Storage container with native lease-based blob locking."*

## 🎯 6. High-Frequency Technical Interview Q&A for These Roles

### Q1: How do you use AI agents (like Claude Code or Antigravity) safely in DevOps without introducing hallucinations into production?
* **Winning Answer:**  
  *"I treat AI agents as rapid scaffolding and analysis assistants, never as unverified executioners. My workflow uses strict human-in-the-loop guardrails:  
  1. I constrain the agent's context with specific schemas, variable definitions, and linting rules.  
  2. Every AI-generated Terraform file must pass automated syntax checking (`terraform fmt -check`, `terraform validate`), static analysis (`tflint`, `tfsec`), and a manual `terraform plan` review before any apply.  
  3. For CI/CD and Kubernetes, every manifest is validated against strict JSON schemas before committing. The AI accelerates drafting, but rigorous automated testing validates correctness."*

### Q2: How do you verify that backups actually work, rather than just assuming they run?
* **Winning Answer:**  
  *"A backup that hasn't been restored is merely an assumption. In my automation scripts, I don't just execute `pg_dump` or `mysqldump` to a cloud bucket; I build automated restore verification workflows. On a scheduled cadence, an ephemeral test container spins up, pulls the latest encrypted dump from storage, restores it into a clean database instance, runs a synthetic data validation query (checking table counts and latest transaction timestamps), and sends an alert with the restore duration and status. If the restore fails, an alert is triggered immediately."*

### Q3: Explain how Kubernetes Pods authenticate to cloud resources securely without storing static API keys.
* **Winning Answer:**  
  *"In AWS, we use **IAM Roles for Service Accounts (IRSA)**; in Azure, we use **AKS Workload Identity**; and in GCP, we use **GKE Workload Identity**.  
  Instead of injecting long-lived cloud credentials into Kubernetes Secrets, we create an OpenID Connect (OIDC) identity provider for the cluster. We annotate the Kubernetes Service Account with the cloud IAM role/identity. When a Pod launches, the Kubernetes projected service account token is exchanged via the cloud STS endpoint for short-lived, least-privilege cloud credentials. This completely eliminates hardcoded secrets and enforces automatic token rotation."*

### Q4: A Linux server is reporting 100% disk utilization, but `du -sh /*` shows only 40GB used on a 100GB disk. How do you troubleshoot this?
* **Winning Answer (RHCSA Rigor):**  
  *"This is a classic issue where files have been unlinked (`rm`), but the file descriptors remain held open by running processes. The disk space cannot be reclaimed until those processes release the file handle.  
  1. I run `lsof +L1` or `lsof | grep deleted` to identify open file descriptors pointing to deleted files.  
  2. Once I find the offending process (often a running web server, database, or logging daemon), I either reload/restart the service (`systemctl reload <service>`) or truncate the file descriptor via `/proc/<PID>/fd/<FD>` to immediately free the space without crashing the application."*
