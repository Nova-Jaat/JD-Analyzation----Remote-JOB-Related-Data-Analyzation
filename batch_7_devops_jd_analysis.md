### High-Frequency Technical Interview Prep for Celebal Technologies:

#### 1. How do you design secure networking in Azure (Hub-and-Spoke Architecture)?
* **Hub VNet:** Houses shared central services: Azure Firewall, VPN Gateway / ExpressRoute, and Azure Bastion.
* **Spoke VNets:** Contain distinct workload environments (e.g., App Tier, Database Tier) peered with the Hub VNet (`VNet Peering`).
* **Isolation & Routing:** User Defined Routes (UDRs) route all outbound spoke traffic through the central Azure Firewall in the Hub for deep packet inspection.
* **Private Connectivity:** Backend PaaS services (Azure SQL, Cosmos DB, Azure Key Vault) are locked down with **Azure Private Endpoints**, assigning them private IPs inside the VNet and disabling public internet access.

#### 2. How do you implement Managed Identities and RBAC in Microsoft Entra ID?
* **Why Managed Identities?** Eliminates credentials stored in code or configuration files. Azure automatically handles identity management and token rotation in Entra ID.
  * **System-Assigned:** Tied directly to a single Azure resource (e.g., an App Service or VM); automatically deleted when the resource is deleted.
  * **User-Assigned:** Independent lifecycle; can be assigned to multiple resources requiring identical permissions.
* **RBAC Granularity:** Assign roles following least privilege at the appropriate scope: Management Group ➔ Subscription ➔ Resource Group ➔ Resource.

#### 3. How do you embed SAST and DAST into Azure DevOps CI/CD Pipelines?
* **SAST (Static Application Security Testing):**
  * Integrated in the build stage before compiling or container packaging using SonarQube or Semgrep.
  * Pipeline fails if the Quality Gate is breached (e.g., Critical/High vulnerabilities, hardcoded secrets).
* **DAST (Dynamic Application Security Testing):**
  * Triggered against an ephemeral staging environment after deployment using OWASP ZAP or Azure Native Defender.
  * Scans active HTTP endpoints for SQL injection, cross-site scripting (XSS), and misconfigured HTTP headers.

### High-Frequency Technical Interview Prep for RoboMQ:

#### 1. How do you design and operate a Multi-Node Kubernetes Cluster for High Availability?
* **Control Plane Resilience:** Deploy an odd number of master nodes (minimum 3) across multiple Availability Zones to maintain **etcd quorum** (`(N/2) + 1`). If one AZ fails, etcd continues leader election without split-brain issues.
* **Worker Node Distribution:** Spread worker node pools across multiple AZs using `topologySpreadConstraints` and `podAntiAffinity` so microservice replicas never all land on the same host or failure domain.
* **Storage & Networking:** Integrate AWS EBS CSI driver with volume binding mode `WaitForFirstConsumer` so persistent volumes match the pod's scheduled AZ.

#### 2. How do you use NMAP and vulnerability scanners in a DevSecOps workflow?
* **Network Surface Auditing with NMAP:**
  * Run periodic automated scans against staging and production subnets: `nmap -sV -sC -p- -T4 <target_cidr>` to detect open ports, unauthorized listening services, and outdated daemon versions.
  * Run unprivileged user scans: verify that no internal Kubernetes node exposes kubelet ports (`10250`, `10255`) or etcd (`2379`) to unauthorized ingress.
* **Application & Container Security:** Combine OWASP ZAP baseline scans in CI/CD pipelines for dynamic testing with Trivy container image scanning to block critical CVEs before deployment.

#### 3. How does Zero-Trust apply to Identity Governance (Hire2Retire context)?
* **Zero-Trust Identity Lifecycle:** Automated provisioning and de-provisioning based on HR trigger events. When an employee departs, automated de-provisioning must instantly revoke IAM roles, OAuth tokens, and directory group memberships across all downstream systems.
* **Principle of Least Privilege (PoLP):** Implement Just-In-Time (JIT) access and role assumption (`sts:AssumeRole`) rather than persistent superuser access, with full audit logging via CloudTrail and SIEM.
