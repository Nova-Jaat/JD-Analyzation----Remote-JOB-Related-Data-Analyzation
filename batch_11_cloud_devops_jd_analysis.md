### 🎙️ RunElix High-Frequency Technical Interview Questions & Model Answers:

#### Q1. Explain how you design an end-to-end CI/CD pipeline using Azure DevOps YAML.
* **Model Answer:**
  * **Structure:** A production Azure DevOps pipeline consists of `trigger`, `variables`, and hierarchical `stages` ➔ `jobs` ➔ `steps` (tasks).
  * **Build Stage (CI):** Triggered on commits or PRs to `main` or feature branches. Uses an Azure-hosted (`ubuntu-latest`) or self-hosted agent. Compiles code, executes unit tests, performs Docker container build (`Docker@2` task), and pushes the image to Azure Container Registry (ACR) using a Service Connection.
  * **Artifact Publishing:** Publishes build artifacts or Helm charts using `PublishBuildArtifacts@1`.
  * **Deploy Stage (CD):** Utilizes `deployment` jobs targeting Azure Environments with approvals/gates. Pulls the verified container image and deploys to Azure App Service (`AzureWebAppContainer@1`) or AKS (`KubernetesManifest@0`).

```yaml
# Sample azure-pipelines.yml
trigger:
  branches:
    include:
      - main

pool:
  vmImage: 'ubuntu-latest'

variables:
  azureSubscription: 'Azure-Production-ServiceConnection'
  appName: 'runelix-web-app'
  acrRegistry: 'runelixcr.azurecr.io'

stages:
- stage: Build_And_Test
  displayName: 'Build & Containerize'
  jobs:
  - job: BuildJob
    steps:
    - task: Docker@2
      displayName: 'Build and Push to ACR'
      inputs:
        command: buildAndPush
        containerRegistry: '$(azureSubscription)'
        repository: '$(appName)'
        dockerfile: '**/Dockerfile'
        tags: |
          $(Build.BuildId)
          latest

- stage: Deploy_Production
  displayName: 'Deploy to Azure App Service'
  dependsOn: Build_And_Test
  condition: succeeded()
  jobs:
  - deployment: DeployJob
    environment: 'production'
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureWebAppContainer@1
            displayName: 'Deploy Container to Azure Web App'
            inputs:
              azureSubscription: '$(azureSubscription)'
              appName: '$(appName)'
              imageName: '$(acrRegistry)/$(appName):$(Build.BuildId)'
```

#### Q2. What is Microsoft Entra ID (formerly Azure Active Directory), and how do you use Service Principals in Azure DevOps?
* **Model Answer:**
  * **Entra ID Overview:** Microsoft's cloud-based identity and access management (IAM) solution. It manages users, groups, application registrations, and role assignments (RBAC) across Azure resources.
  * **Service Principal:** An identity created in Microsoft Entra ID for use with automated tools, applications, or CI/CD pipelines (like Azure DevOps) to access specific Azure resources.
  * **Integration with Azure DevOps:** Rather than using personal admin credentials, Azure DevOps connects to Azure via an **Azure Resource Manager (ARM) Service Connection**, which authenticates using a Service Principal (or Workload Identity federation).
  * **RBAC Scoping:** We assign the Service Principal the minimal required role (e.g., `Contributor` on a specific Resource Group or ACR, rather than `Owner` at the entire subscription level) following least-privilege principles.

---

#### Q3. How do you configure network isolation in Azure using VNets and Network Security Groups (NSGs)?
* **Model Answer:**
  * **Virtual Network (VNet):** A private, isolated network in Azure with a private IP address space (e.g., `10.0.0.0/16`).
  * **Subnet Segmentation:** Divide the VNet into subnets based on application tiers (e.g., Public/Web Subnet `10.0.1.0/24`, Application Subnet `10.0.2.0/24`, and Private Database Subnet `10.0.3.0/24`).
  * **Network Security Groups (NSGs):** Stateful firewalls containing inbound and outbound security rules.
    * Rules are evaluated based on **Priority (100 to 4096)**; lowest number takes precedence.
    * Inbound rule: Allow HTTP/HTTPS (ports 80/443) from the Internet to the Web Subnet only.
    * Database Subnet rule: Allow incoming traffic on port 5432/3306 *only* from the Application Subnet CIDR, with an explicit deny-all rule for all other traffic.
  * **Associations:** Associate NSGs directly at the Subnet level for consistent policy enforcement across all NICs attached to that subnet.
