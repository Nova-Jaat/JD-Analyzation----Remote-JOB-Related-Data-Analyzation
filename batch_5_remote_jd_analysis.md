    * Ability to configure: **IAM, S3, EC2, Lambda, CloudWatch, VPC basics, Security Groups**.
    * Clear English documentation (B2 level or higher).
    * Screen recording with clean audio and clear execution steps.
* **Why You Win:** You configure these exact services every single day. Your RHCSA and Linux CLI background means your terminal and console workflows are clean, structured, and error-free.

#### 5 Ready-to-Execute AWS Task Concepts You Can Submit to SuperAnnotate:
When SuperAnnotate asks you for task proposals, pitch these exact real-world scenarios:

1. **Task 1: Least-Privilege IAM Policy for S3 Bucket Access**
   * *Scenario:* Create an IAM policy restricting an EC2 instance or developer role to `s3:GetObject` and `s3:PutObject` on a specific bucket prefix (`/uploads/*`), with an explicit deny on non-SSL (`aws:SecureTransport: false`) connections.
2. **Task 2: Automated EC2 Health Monitoring & CloudWatch Alarm**
   * *Scenario:* Provision a t3.micro web server in a public subnet, configure an EC2 StatusCheckFailed CloudWatch alarm, and attach an SNS topic to notify administrators upon instance degradation.
3. **Task 3: Serverless S3 Image Processor via AWS Lambda**
   * *Scenario:* Deploy a Python Lambda function triggered automatically when an image is uploaded to an S3 source bucket, extracting metadata and writing a JSON manifest to a target bucket.
4. **Task 4: VPC Security Group & Network Segmentation**
   * *Scenario:* Configure a 2-tier VPC architecture where an application security group in a public subnet only allows inbound HTTP (80/443), while a private database security group strictly allows inbound traffic on port 5432 (PostgreSQL) originating from the application security group ID.
5. **Task 5: CloudWatch Log Group Subscription & Metric Filter**
   * *Scenario:* Create a metric filter on an application's CloudWatch Log Group to count occurrences of `HTTP 500` errors, creating a custom metric and alarm threshold.
