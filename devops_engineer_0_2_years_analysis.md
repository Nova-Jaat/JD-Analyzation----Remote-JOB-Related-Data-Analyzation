### 2. Docker & Container Security Best Practices
When asked: *"What are your golden rules for writing production Dockerfiles?"*

1. **Multi-Stage Builds:** Compile and assemble dependencies in a builder stage (e.g., `golang:alpine` or `node:alpine`) and copy only the compiled binary or stripped runtime to a minimal final image (such as `alpine` or Google's `distroless`). This reduces image size from ~800MB to under 50MB.
2. **Never Run as Root:** Explicitly create an unprivileged user and group (`RUN addgroup -S appgroup && adduser -S appuser -G appgroup`) and declare `USER appuser`.
3. **Layer Caching Optimization:** Place rarely changing instructions at the top (e.g., `COPY package.json .` and `RUN npm install`) and application source code (`COPY . .`) near the bottom so code changes don't invalidate dependency caches.
4. **Use Explicit Tags:** Avoid `FROM node:latest` or `FROM alpine:latest`; always pin semantic version tags or sha256 digests (`FROM alpine:3.19@sha256:...`) to ensure reproducible builds.
5. **Clean Package Manager Caches:** Combine update, install, and cache cleanup in a single `RUN` layer (`RUN apt-get update && apt-get install -y --no-install-recommends pkg && rm -rf /var/lib/apt/lists/*`).

### 3. Kubernetes Orchestration & Troubleshooting
When asked: *"A microservice Pod is stuck in `CrashLoopBackOff`. Walk me through your step-by-step triage process."*

* **Step 1: Check Pod Status & Restart Count:**
  ```bash
  kubectl get pods -n <namespace> -o wide
  ```
* **Step 2: Inspect Pod Events & Configuration:**
  ```bash
  kubectl describe pod <pod-name> -n <namespace>
  ```
  *Check the `Events` section for OOMKilled (exit code 137), failed liveness probes, missing secrets/ConfigMaps, or image pull errors.*
* **Step 3: Retrieve Container Logs (Including Previous Crashed Instance):**
  ```bash
  kubectl logs <pod-name> -n <namespace> --previous
  ```
  *The `--previous` flag is critical because standard `kubectl logs` might show nothing if the container died immediately upon startup.*
* **Step 4: Check Resource Limits:**
  *If exit code is `137`, the container exceeded its `limits.memory` and was terminated by the Linux OOM killer. Increase memory limit or optimize application memory leaks.*
* **Step 5: Shell into Pod (if briefly running) or Test Locally:**
  *Inspect environment variables and database connectivity (`nc -zv <db-host> <port>`).*

### 4. Infrastructure as Code (Terraform) Mastery
When asked: *"How do you handle state management, locking, and team collaboration in Terraform?"*

* **Remote Backend with Encryption:**
  - Store the `terraform.tfstate` in Amazon S3 (with server-side encryption SSE-S3/KMS and bucket versioning enabled) or Google Cloud Storage bucket.
* **State Locking:**
  - Utilize an **Amazon DynamoDB table** (with `LockID` string primary key) or GCS native locking to prevent simultaneous `terraform apply` runs by multiple engineers.
* **Modular Codebase:**
  - Structure code into reusable modules:
    ```
    ├── modules/
    │   ├── vpc/
    │   ├── eks_cluster/
    │   └── security_groups/
    └── environments/
        ├── dev/ (main.tf, variables.tf, terraform.tfvars)
        └── prod/ (main.tf, variables.tf, terraform.tfvars)
    ```
* **Drift Detection:**
  - Regularly execute scheduled `terraform plan -detailed-exitcode` in CI/CD to catch any out-of-band manual console changes.

### 5. Scripting: Bash & Python Automation
When asked: *"When do you write a Bash script versus a Python script for DevOps tasks?"*

* **Use Bash for:**
  - Quick, native OS-level utilities (piping `grep`, `awk`, `sed`, `systemctl`, `journalctl`, `tar`, `rsync`).
  - Container entrypoint scripts (`entrypoint.sh`).
  - Server initialization and cloud-init user-data scripts.
* **Use Python (or Go) for:**
  - Interacting with cloud SDKs (AWS Boto3, GCP Cloud Client Libraries) to automate resource discovery, snapshot cleanup, or cost reporting.
  - Parsing complex nested JSON/YAML structures from APIs.
  - Building custom Kubernetes webhooks, Slack/Discord notification bots, or GenAI integrations.
